RDP Issue Monitor v1.2.1 安装说明（API 认证修复）

本版本是在 v1.1 基础上升级，不需要建立新的 Repository。

需要替换/新增的文件：
1. 替换 .github/workflows/rdp-monitor.yml
2. 替换 .github/scripts/rdp_issue_monitor.py
3. 替换 tests/test_rdp_issue_monitor.py

重要：保留 Repository 根目录现有的 monitor-state.json 和 compatibility-candidates.json，不要手动删除。

升级行为：
- 程序会自动把 compatibility-candidates.json 从 schema_version 1 迁移至 2。
- 首次 v1.2 执行会自动回溯最近 30 天，重新丰富现有 Issue 的版本关系、失败信号、重复关系和来源时间。
- 已有 INI Candidate、SHA-256 和来源会保留，不会因升级而清空。
- 数据库仍使用 compatibility-candidates.json；新增的 issue-level 资料存放在其中的 "issues" 对象。

GitHub 网页安装步骤：
A. 更新 Workflow
   1. 打开 Repository johnson4860/rdp。
   2. 打开 .github/workflows/rdp-monitor.yml。
   3. 点击 Edit，将本包同名文件完整内容替换进去。
   4. Commit changes。

B. 更新 Python 程序
   1. 打开 .github/scripts/rdp_issue_monitor.py。
   2. 点击 Edit，将本包同名文件完整内容替换进去。
   3. Commit changes。

C. 更新测试文件
   1. 打开 tests/test_rdp_issue_monitor.py。
   2. 点击 Edit，替换完整内容；如果文件不存在则建立同路径文件。
   3. Commit changes。

运行：
1. 打开 GitHub > Actions > RDP Update Monitor。
2. 点击 Run workflow > Run workflow。
3. 等待 Test compatibility parser and classification 与 Monitor 两个步骤通过。
4. Workflow 会提交 monitor-state.json 和 compatibility-candidates.json。
5. 打开 Run Summary 查看每个 Issue 的分类、版本关系、失败信号、INI 完整性和来源。

v1.2 新增分类：
- Issue classification: reported_failure / duplicate_issue / maintainer_labeled_invalid / compatibility_request / general_activity。
- Candidate review_classification: reported_failure / incomplete / unverified。
- "reported_failure" 只表示 Issue 文字中检测到失败描述，不代表已经证明 INI 导致故障。
- "Not RDP Wrapper bug" 等文字会作为 triage note 保存，不会自动判定配置有效。
- Windows 标题中的 10.0.x.x 会单独记录为 title version hint；只有文本明确将版本与 termsrv/termsrv.dll 关联时，才归类为 termsrv.dll version。

安全边界：
- Monitor 只读取公开 GitHub Issue、评论和元数据。
- 不会下载或运行 termsrv.zip / 其他附件。
- 不会自动修改、安装或发布生产 rdpwrap.ini。
- 不会因为 Issue Closed、Duplicate 或某个评论而把 Candidate 自动标记为 Verified。
- `compatibility-candidates.json` 中的候选配置仍须人工审核并在隔离测试环境验证。


v1.2.1 修复内容：
- 明确在监控 Step 注入 GitHub Actions 自动生成的 GH_TOKEN。
- 权限声明增加 issues: read；保留 contents: write 以提交监控数据库。
- Python 程序启动时先检查认证状态和 REST API core quota。
- 如果 GH_TOKEN 缺失，程序立即停止，不再匿名请求 GitHub API。
- 日志只显示 token 是否存在及 quota，不会输出 token 内容。

不需要建立 Personal Access Token，也不需要在 Repository Secrets 手动新增 GITHUB_TOKEN。
GITHUB_TOKEN 是 GitHub Actions 自动提供的 token，由 Workflow 的 ${{ secrets.GITHUB_TOKEN }} 引用。


本次错误说明（HTTP 403 rate-limit remaining=0, message 显示 IP address）：
这代表之前的请求以未认证方式访问 GitHub API，触发公开匿名 API 的 60 次/小时限制。
v1.2.1 在 monitor step 明确传入 GH_TOKEN，并在正式扫描前调用 /rate_limit 验证认证状态。
正常情况下会在 Actions Log 看到类似：
  GitHub API authentication: token supplied (value hidden)
  GitHub REST core quota: 999/1000 requests remaining
如果 token 缺失，程序会在发送 API 请求前停止，避免再次消耗匿名额度。

安装 v1.2.1：
1. 替换 .github/workflows/rdp-monitor.yml
2. 替换 .github/scripts/rdp_issue_monitor.py
3. 替换 tests/test_rdp_issue_monitor.py
4. Commit changes 后，手动 Run workflow。
5. 在 Log 先确认 GitHub REST core quota 显示的 limit 明显高于 60（通常为 1000（GITHUB_TOKEN 在 Actions 中按 Repository 计））。
6. 再确认 Monitor 主步骤能继续扫描 Issues。

无需自己建立 Personal Access Token；无需手动新增 Repository Secret。
程序不会输出 token 本身，也不会下载或发布任何 INI。
